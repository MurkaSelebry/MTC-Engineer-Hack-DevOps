# Обоснование технических решений

Источники проверены 4 октября 2026 года. Ниже — рекомендации upstream и их применение в этом стенде. Наличие версии в матрице совместимости не заменяет сквозную проверку развернутого кластера.

1. **Согласовать cgroup driver kubelet и containerd.** На Ubuntu с systemd используем `cgroupDriver: systemd` и `SystemdCgroup = true`. Для containerd 2.x секция конфигурации отличается от 1.x; автоматизация учитывает установленную версию. Это устраняет конфликт двух менеджеров cgroups. [Kubernetes: Container Runtimes](https://kubernetes.io/docs/setup/production-environment/container-runtimes/#systemd-cgroup-driver).

2. **Проверять совместимость Calico и пересечения сетей до установки.** Документация Calico 3.32 указывает тестирование с Kubernetes 1.34–1.36; Kubernetes 1.35.9 входит в этот диапазон. Pod CIDR `10.244.0.0/16` и Service CIDR `10.96.0.0/12` должны отличаться от сетей хоста/VPN. VXLAN не требует маршрутизации Pod CIDR облачным провайдером; при нескольких узлах нужен UDP 4789 между ними. [Требования именно Calico 3.32](https://github.com/tigera/docs/blob/master/calico_versioned_docs/version-3.32/_includes/partials/_system-requirements.mdx).

3. **Обновлять Envoy Gateway и Gateway API согласованно.** Ветка Envoy Gateway 1.9 использует Gateway API 1.6.1 и тестируется с Kubernetes 1.33–1.36. Закреплены Envoy Gateway 1.9.2 и архив Helm chart; CRD берутся из соответствующей поставки, а не из случайной версии `latest`. [Матрица совместимости](https://gateway.envoyproxy.io/news/releases/matrix/), [исходники релиза 1.9.2](https://github.com/envoyproxy/gateway/tree/v1.9.2).

4. **Явно выбрать способ внешнего доступа.** NodePort 30080/30443 не требует облачного LoadBalancer. `externalTrafficPolicy: Cluster` позволяет узлу передать запрос доступному Envoy endpoint; это важно при последующем добавлении узлов. Порты задаются поддерживаемым patch Service в EnvoyProxy. NodePort сам по себе не создает публичный IP и не обходит firewall. [EnvoyProxy API 1.9.2](https://github.com/envoyproxy/gateway/blob/v1.9.2/api/v1alpha1/shared_types.go), [Kubernetes: NodePort](https://kubernetes.io/docs/concepts/services-networking/service/#type-nodeport).

5. **Доказывать сбор метрик запросом, а не установкой Prometheus.** PodMonitor выбирает реальные Envoy pods и порт `metrics` 19001 с `/stats/prometheus`. Проверяются все targets и рост счетчика после свежего scrape. Метрики трафика ограничены listener prefixes `http-10080|https-10443`: административные endpoints и probes тоже имеют HTTP counters и без фильтра искажают результат. [Envoy Gateway: Proxy Metrics](https://gateway.envoyproxy.io/docs/tasks/observability/proxy-metric/), [Prometheus Operator: troubleshooting](https://prometheus-operator.dev/docs/platform/troubleshooting/).

6. **Оставлять место для WAL и рабочих данных Prometheus.** Используем retention 24h / 3 GB блоков на PV 5 GiB. Ограничение размера не является лимитом всего каталога: WAL, текущая head series и операции компакции требуют запаса. Размеры рассчитаны на демонстрационную нагрузку; свободное место контролируется отдельно. [Prometheus: Storage](https://prometheus.io/docs/prometheus/latest/storage/).

7. **Разбирать CRI до JSON приложения.** Порядок: CRI envelope → объединение `P/F` fragments → JSON access log. У concat отдельная идентичность для файла/контейнера и stdout/stderr; таймаут незавершенной записи направляется в обычный output. Текст error log сохраняется в `message`. Это проверяется настоящим Fluentd процессом и payload Loki. [CRI parser](https://github.com/fluent/fluent-plugin-parser-cri), [concat](https://github.com/fluent-plugins-nursery/fluent-plugin-concat).

8. **Сохранять позиции чтения и ограничивать очередь.** `pos_file` и file buffer находятся на persistent hostPath; `follow_inodes` помогает при ротации файлов. Буфер ограничен 512 MiB, повторяет отправку с backoff и при заполнении блокирует дальнейшую запись в очередь. Это переживает краткую недоступность Loki, но не гарантирует exactly-once или сохранность логов при длительной ротации. [Fluentd tail](https://docs.fluentd.org/input/tail), [buffer section](https://docs.fluentd.org/configuration/buffer-section).

9. **Не превращать каждый запрос в отдельный Loki stream.** В labels передаются `app`, `namespace`, `stream`; URI, UUID и client IP остаются полями JSON. Loki может добавлять собственные labels с небольшим набором значений, например `service_name`. Это ограничивает cardinality индекса и сохраняет поиск по содержимому записи. [Loki: Label best practices](https://grafana.com/docs/loki/latest/get-started/labels/bp-labels/).

10. **Настроить удаление Loki полностью.** Для одной VM выбран Monolithic/filesystem с TSDB v13, одной replica и PV 8 GiB. Retention 24h дополняется compactor, постоянным working directory, `delete_request_store: filesystem`, index period 24h и задержкой удаления 1h. Filesystem store не очищает данные по факту заполнения диска. [Monolithic installation](https://grafana.com/docs/loki/latest/setup/install/helm/install-monolithic/), [retention](https://grafana.com/docs/loki/latest/operations/storage/retention/).

11. **Проверять неявные загрузки внутри закрепленных компонентов.** Зафиксированный chart Grafana сам по себе не исключает скачивание дополнительных plugins при старте: это обнаружено в журнале развернутой версии 13.2.3. `preinstall_disabled: true` и `preinstall_auto_update: false` отключают такой путь; встроенных Prometheus/Loki datasource и panels достаточно. Fluentd собирается заранее из base digest и Gemfile.lock с checksums; Pod ничего не устанавливает. [Точные настройки Grafana 13.2.3](https://github.com/grafana/grafana/blob/v13.2.3/conf/defaults.ini), [Kubernetes: image digests](https://kubernetes.io/docs/concepts/containers/images/#image-names).

12. **Учитывать ограничения локальных PV.** `WaitForFirstConsumer`, node affinity и отдельные PVC selectors обеспечивают правильную привязку диска; `Retain` защищает данные от автоматического удаления при удалении claim. Они не обеспечивают репликацию или перенос данных при потере узла. [Kubernetes: local volumes](https://kubernetes.io/docs/concepts/storage/volumes/#local), [StorageClass volume binding](https://kubernetes.io/docs/concepts/storage/storage-classes/#volume-binding-mode).

Профиль **одна VM, 8 vCPU, 16 GB RAM, диск от 50 GB** — инженерный выбор для ограниченного демонстрационного потока, не обещание производительности при произвольной нагрузке. PV 5+8+1 GiB и буфер 512 MiB не учитывают ОС, образы, сборочный cache и WAL; кроме того, PV capacity не является filesystem quota. Нужен запас диска и контроль его роста. Один узел, local storage и локальный CA сознательно исключают HA и публичный доверенный TLS. Prometheus исполняет alert rules, но Alertmanager и внешняя доставка уведомлений не настроены. Логи и метрики доступны через административный tunnel/port-forward.
